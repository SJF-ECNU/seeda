# 种系选择与标准介绍

## 快速选择

```bash
seeda strains                    # 交互终端显示名称、简介、ID，★ 为默认
seeda strains default coding-plus
seeda seed                       # 选择器：预选默认，可搜索其他种系
seeda seed coding-plus           # 名称或完整ID，直接播种
```

选择器支持输入名称、简介或场景关键词搜索，↑↓ 选择，Enter 确认，Esc/Ctrl+C 取消。选中项下展示五项介绍，PgUp/PgDn 浏览长介绍。旧种系没有介绍时明确显示缺失，不补造验证结论。取消不播种项目，终端模式恢复。

首次交互运行 `seeda` 也先选择种系，再进入 Agent TUI。带任务参数的启动或非交互 `seed` 使用已设默认；未设置默认时使用 origin。默认 ID 保存在全局库 SQLite，仅影响未来播种。已经初始化的项目不会切换版本或再次显示初始化选择器。

`seeda strains` 重定向时保持 JSON，包含 intro 和 is_default，方便 Agent 或脚本读取。

## 发布介绍

新发布必须附带五个非空文本字段：简介 summary、改进 improvements、适用场景 scenarios、限制与依赖 limitations、验证情况 validation。Agent 可依据已保存改动和实际证据起草；验证字段是发布者的说明，未验证应明确写未验证，平台不把它当作自动认证。

例如 intro.json：

```json
{
  "summary": "改善 Bash 失败信息的种系",
  "improvements": "保留退出码，并明确显示失败原因",
  "scenarios": "需要频繁运行命令和排查失败的编码项目",
  "limitations": "需要 Node.js 24.14+、Git、npm；尚未验证 Windows",
  "validation": "未验证：尚未执行独立任务验证"
}
```

```bash
seeda publish clearer-bash --intro intro.json
seeda publish clearer-bash VERSION_ID --intro intro.json
```

Agent 管理工具对应 `publish(name, introduction, version?)`，introduction 为上述五字段对象。来源、Git commit、发布时间由系统记录；重复名称仍拒绝。标准介绍保存在 catalog 关联表，旧种系仍可播种，代码与项目历史不被修改。

已有后台管理进程需要重启才能加载新发布规范；保存的旧 Agent 版本不会因入口变化自动升级，其发布工具说明可能还没有 introduction 字段，可以使用新版 CLI 发布或沿用候选升级流程。当前全局 origin 也不会被自动替换。
