# 1.0.1 种系更新对比

比较对象：仓库基础实现（提交 `6c2b804`）与本机 `seeda-v1.0.1` 实际运行版本 `da890d1d`。以源码和实际测试核对，版本描述仅作定位线索。

| 更新 | 结论 | 本次处理 |
|---|---|---|
| Bash 清理异常与进程组 PID 保护 | 必须回收。`exit` 等异步回调中抛出 `kill EPERM` 会终止整个 worker；测试非零退出应只是工具失败 | 合入基础代码；权限失败记录工具错误，并尝试直接终止 child，保留进程树清理 |
| 模型请求限次重试 | 必须回收。暂时性网络、限流和服务故障可恢复 | 默认最多 3 次尝试，带退避；修复原 TimeoutError 被当成取消而实际不重试的问题 |
| 流式重放与取消约束 | 必须保留。重试不能重复已有正文或取消后继续请求 | 已流出正文不重放；外部取消、400/401/404不重试；证书等永久配置问题不重试 |
| usage 归一化与状态栏 | 有用。基础 TUI 已支持显示，但基础 Agent 的指标事件接线不全 | 回收请求 usage 归一及核心事件、重试状态接线；1M token窗口保留 |
| 多行粘贴 | 有用且已进入稳定前端，避免一次粘贴被拆成多条提交 | 维持现有实现和回归，属于前端安装更新，不再随种系发布 |
| `web_fetch` | 有用的可选能力。读取HTTP页面并抽取正文，无额外SDK | 本次保留在进化种系，不默认增加到基础工具；不会执行页面JavaScript，不等同浏览器 |
| `web_search` | 有用的可选能力。Brave API返回结构化搜索结果 | 本次保留在进化种系；需要BRAVE_API_KEY，限流和配置需单独处理 |
| 中文交流规则 | 项目规则，与用户习惯相符 | 当前项目种系保留，不把项目偏好自动设为所有用户的强制规则 |
| 全局命令跟随当前版本CLI | 会耦合恢复入口与进化实现 | 已被稳定前端架构替代，不能回收旧薄壳方式 |

## 重试的边界

模型请求可在未产生界面正文或工具执行前，对暂时性失败做有限重试。单次超时与用户取消不同：前者可再次尝试，后者必须立即结束。已流出正文后断流，本次请求报错，不自动把正文重新输出一遍。

Bash 不统一自动重试。失败命令可能已经修改文件、写入数据或发送请求；直接重放会重复副作用。`npm test` 失败应把输出、退出码交给 Agent 判断，再修复或重新执行。工具失败不应结束终端或会话。

## 本次验证

本地HTTP实测：503后成功、单次超时后成功、401只一次、正文断流不重放。真实Bash非零退出后下一轮Agent请求仍可继续；注入进程组EPERM时返回错误，不从异步回调抛出。基础完整69项回归和类型检查通过。

这些验证不等于真实提供商始终可用，也不证明每个网络工具已接入重试。本次回收范围是模型请求与会话稳定性；网页工具的重试策略仍是后续可选工作。
