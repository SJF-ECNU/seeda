# 自身指令、通用记忆与项目规则

Agent 每次请求和压缩都从当前实际实现版本读取自身文件，从工作项目读取项目规则。两者不要求处于同一目录，接替或回退不复制、不覆盖项目规则。

| 内容 | 来源 | 生命周期 |
|---|---|---|
| 自身工作指令 | 实现版本 `.agents/self/INSTRUCTIONS.md` | 随 draft、submit、evaluate、promote、rollback |
| 通用工作记忆 | 实现版本 `.agents/self/MEMORY.md` | 随自身版本；跨任务保留，可回退 |
| 项目规则 | `cwd/AGENTS.md` | 随项目；每次请求重读 |
| 项目 Skills | `cwd/.agents/skills/*/SKILL.md` | 维持原有按需读取方式 |
| 会话历史 | 原 session JSONL | 随会话，独立于上述文件 |

自身文件根目录由实际执行的核心模块位置确定：托管主实例使用选中版本；候选使用自己的版本（容器中为 `/candidate`）；直接模式使用安装的核心。不能通过改变任务cwd把项目中的同名 `.agents/self` 文件当成Agent自身记忆。

自身规则和通用记忆以独立标识段进入系统上下文，项目规则保留原来的项目段。用户当前要求优先；通用记忆是有适用范围的经验，不是覆盖当前要求或扩大权限的授权。读取成功不证明模型遵守，加载生效不等于能力提高。

## 如何改造

通过 management 获取 draft，只在返回目录中编辑 `.agents/self/INSTRUCTIONS.md` 或 `.agents/self/MEMORY.md`；submit、evaluate、查看证据、decide、promote。这些文件已属于现有 `.agents` Git快照路径，无需额外存储机制。不要编辑保留版本原文件，也不要将安装仓库的根AGENTS.md误当自身指令。

通用记忆适合保存跨任务、证据明确且注明适用条件的经验。当前题答案、用户项目私有知识和凭据不应传播到种系。产品不会自动从聊天提取或写入这份记忆。项目知识仍通过项目文件或可选Project Memory Skill维护。

候选在独立workspace运行，所以默认没有主项目的AGENTS.md和Skills；验证需要的项目规则应作为自建输入显式准备。检验加载必须观察候选实际模型请求或其运行记录，不能仅在实现目录手动调用加载函数后声称主运行生效。

## 运行证据

每次请求的JSONL包含 `instructions` 记录，恢复后由 `runtime_records` 的每个 run 的 `instructions` 字段提供来源：kind、path、loaded、characters。kind分别为self_instructions、self_memory、project_rules、project_skill。loaded表示该来源已成功读取，characters是源文件字符数，Skills仅以名称、描述和路径加入系统上下文，正文仍按需读取。没有复制指令或记忆正文，也不生成Hash。

旧会话没有此字段表示未知；缺文件时loaded=false，不伪造已加载。旧实现版本本身不会因安装源码升级自动获得新加载器。采用新加载器但没有新自身文件的旧快照可继续使用项目规则，不会自动把根AGENTS.md迁成自身指令。

## 验证

`tests/instruction-context.test.ts`覆盖来源分离、旧文件缺失及请求/压缩后元数据重载；`tests/instruction-runtime.test.ts`使用本地HTTP模拟模型，在真实Supervisor与Seatbelt候选中检查实际模型输入，覆盖接替、新会话、恢复会话、回退及项目规则保持。测试不调用付费模型，不证明自主改造或迁移收益。

运行入口与版本语义见 [[docs/版本守护与RSI运行指南]]；运行计量见 [[docs/reliable自身运行记录设计与验证]]。
