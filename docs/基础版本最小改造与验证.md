# 基础版本最小改造与验证

当前工作树实现了结构化执行反馈、管理调用简化和宿主选择的本地/Docker命令执行。尚未提交发布、设默认或升级已有项目；Terminal-Bench实验仍暂停。

## 执行反馈

沿用现有事件、session JSONL和runtime_records，在可用时提供failure对象：stage（model/tool/runtime/evaluation）、reason、可选code和固定事实summary。模型失败有feedback事件，工具结束和请求结束可携带failure，恢复会话后可查询；旧记录缺少字段保持未知。

例如模型连接拒绝可以给出stage=model、reason=model_network、code=ECONNREFUSED；命令退出17给出tool/nonzero_exit/17，不猜测它是题目答案错误或环境故障。摘要不复制任意error.message、响应或凭据。原始工具返回和原日志不被统一包装替代。

completed表示执行结束，不表示任务正确或质量改善。usage未返回时保持未知，不补零；已有可得用量不重复计量。基础版不解析Terminal-Bench评分文件，也不自动决定是否重试。

## 自改操作

原status/draft/submit/evaluate/evidence/decide/promote/rollback继续可用。draft补充source_version/source_commit；submit补充source_version/draft。

evaluate直接返回有界answer（最多4000字符）和error（最多2000字符）及截断标记、来源/候选版本、sandbox、证据路径，以及duration_ms、recording_complete、model_calls、tool_calls、tool_failures、usage、missing_usage。详细内容仍从evidence读取；无可用记录时摘要字段为null，不能误读成零成本。候选记录和回答是执行证据，不是独立质量裁决。

模型management和Supervisor.manage可以显式合并接受与接替：

```json
{"operation":"promote","version":"候选ID","evaluation":"评测ID","reason":"采用理由","acceptReason":"已查看的验证证据及接受理由"}
```

没有acceptReason时仍要求先decide accept。提供时先检查来源、候选、完成状态、忙状态和理由，复用现有接受记录与切换流程。仍在当前请求结束后接替，不自动接受、不跳过沙箱、保留旧版本回退。若接受已写入但接替出错，响应明确报告该部分结果，status可核对；不会自动再跑候选。CLI旧命令保持兼容，本期没有新增CLI位置参数。

常见管理路径从7次调用减到4次（draft、submit、evaluate、promote），需要深入证据仍可单独调用evidence。记忆与自身指令继续随Git版本走同一验证流程，不提供免评测保存通道；读取成功不证明内容正确。

## 本地与Docker执行

Bash模型参数保持command/cwd/timeout，由宿主选择执行环境。普通启动及直接模式默认本地。集成程序可以绑定已经准备好的容器：

```typescript
const supervisor = new Supervisor(store, hostProjectDirectory, {
  kind: 'docker', container: 'caller-owned-task-container', cwd: '/app',
});
await supervisor.start();
```

第三参数是宿主API，不是模型工具参数。hostProjectDirectory仍用于项目规则和会话；Bash默认cwd为所选容器路径，工具描述及返回environment说明实际命令环境。容器必须已有bash、GNU timeout、grep、awk及Linux /proc；调用方负责镜像、挂载、用户与资源配置。此执行器不创建容器，不向容器注入模型凭据，也不额外授予Docker socket。

同一能力版本可在两个环境执行，无需替换bash.ts/worker.ts。Docker不存在、不可访问或cwd无效时失败，不在宿主回退执行。工具额外container/mounts/environment参数会被拒绝。输出仍默认截断至16384bytes并留完整产物；Docker完整输出位于宿主路径，artifact_location=host。候选在自身环境内的日志标记execution。

宿主命令通过现有worker IPC和一个短生命周期的宿主command guardian执行。引入guardian的具体原因是：Supervisor被SIGKILL时不能执行finally，普通父进程回调不足以清理已发出的命令；guardian收到IPC断连后仍可取消并完成回收。它不属于Agent快照，不是常驻新服务。

本地保留原有进程组清理；Docker用每调用标识回收继承标识的子孙进程，包括setsid后代。标识是清理作用域，不是安全隔离，不能宣称能阻止恶意进程清除环境变量逃逸；需要安全隔离的候选仍使用原有Seatbelt/容器沙箱，不能获得主实例执行通道。Docker daemon失联会导致无法确认回收，此时明确失败，不宣称已清理。连接可用时取消、超时和Supervisor被杀后的清理已实际验证。

旧Agent没有接入能力标识时本地行为保持；Docker绑定明确拒绝，不偷偷切回本地。默认种系和保存的旧版本不会自动获得新代码。

## 实际验证与限制

Node24.18.0、macOS、真实Docker和Seatbelt；模型使用本地HTTP/SSE确定性服务，没有付费提供商调用。

- 最终默认并发完整回归138/138通过，0跳过，约43.47秒；TypeScript与OpenSpec严格校验通过。
- 同一原生版本在本地与Docker实际写读文件，验证空间cwd、输出100000bytes的截断与完整产物、非0、超时和取消、容器不存在不回退。
- Docker超时/取消覆盖普通子进程和setsid孙进程；Supervisor实际SIGKILL后，本地shell/子进程、Docker shell/普通子进程/setsid后代/孙进程均停止。最终整套测试记录具体PID状态，不以模拟取消代替。
- 真实Seatbelt候选不能读取宿主测试秘密、未继承主执行配置，伪造command请求被拒绝；旧worker本地兼容、Docker能力缺失拒绝。
- 原生旧/合并管理流程、失败验证、过期来源、错误候选、空理由、忙状态、请求边界接替、接替失败、重启、实际指令/记忆加载和回退均覆盖。
- 最终整套测试中的确定性操作比较：7→4管理调用、返回23758→5756bytes；耗时约3837→3868ms，未测得本次并发运行墙钟下降。只能证明操作和返回量减少，不能推断真实模型tokens或收益。

保留首次完整测试失败日志：新增fixture临时路径超macOS socket长度，以及旧测试用精确ready字符串注入延时失效。已缩短fixture路径、调整注入位置；随后重新执行完整套件通过，不用单项通过代替全量结论。

证据：.seeda/validation/minimal-evolution-foundation/full-test.log（首次）、full-test-final.log（最终）、checks.log、verification.json。测试不证明Agent自主决定改造或未见任务收益；未恢复正式实验。
