# 最小 Coding Agent 蓝本

目标：首先实现可连续对话、使用本地终端完成编程任务的 CLI；自进化是后续目标。本蓝本是基于源码调研形成的建议，尚未实现或进行模型实测。语言、模型提供商和 SDK 尚未确定。

## 最小闭环

外层负责多轮用户交互，内层负责一个用户请求内的模型与工具往返。二者共享同一个会话。

1. 用户输入进入当前会话。
2. 组装系统指令、工作目录、项目规则、Skill 目录和有效历史。
3. 请求模型，显示文本输出，等待完整响应。
4. 正常完成且包含工具调用：验证工具名称和参数，按顺序执行，逐项回传对应结果，然后返回第 2 步。
5. 正常完成且没有工具调用：结束本次用户请求，回到输入提示符。
6. 取消、请求失败、输出截断或协议异常：明确报告中断或失败，返回可交互状态，不当成正常完成。

文字输出可能与工具调用同时出现，不能仅因出现文字而停止。工具只在参数完整并验证通过后执行。一个响应内的多个工具调用第一版顺序执行，不引入并行调度。

## 第一版必需实现

| 能力 | 最小行为 | 必要原因 |
| --- | --- | --- |
| CLI | 输入、显示回答与工具执行状态、Ctrl+C 取消当前请求、退出 | 完成用户交互，避免命令卡住后失去控制 |
| 单一模型接入 | 一种提供商协议；配置模型、端点、凭据来源；识别文本、完整工具调用、结束原因与请求失败 | 提供决策来源；不同时实现多家适配和登录体系 |
| Agent loop | 模型、工具、结果回传的内循环；正常结束返回用户 | 实际执行多步任务 |
| 会话与上下文 | 保存历史、构建当前模型输入、读取启动目录的 AGENTS.md | 连续对话依赖历史与项目规则 |
| 工具调度 | 工具名、描述、参数 schema、执行函数；调用与结果对应 | 避免将模型文本误当成命令；后续可添加工具 |
| Bash 工具 | command、cwd、timeout；输出、退出码、失败原因；超时与取消清理子进程 | 读、写、搜索文件及执行测试的通用执行能力 |
| 输出与请求边界 | 工具输出有界，超长内容保存到会话文件并返回路径；模型请求可以取消；请求失败不自动重跑命令 | 防止输出淹没上下文，避免重复副作用 |

内置记忆仅限 session，采用简单本地 JSONL；不建设长期语义或项目知识数据库。保存用户消息、完整模型响应、工具调用与结果；凭据配置不写入会话。当前模型协议要求的额外响应项也必须保留，不能只保存可见文本。会话文件属于本机运行数据，不自动加入 Git。

恢复至少支持加载已完成调用与结果后继续对话。若退出时命令已启动但结果未记录，标记结果未知，检查现场后继续，不能自动重放。完整崩溃恢复和自动复活以后再实现。

Bash 每次启动独立非交互进程。默认 cwd 是启动 CLI 时的项目目录；单次 cd 或 export 不自动继承到下一次调用。先支持正常会退出的命令；持续运行的开发服务器、PTY、交互式密码输入和后台任务管理延后。

## 基于用户目标保留的两项基础能力

它们不属于单次模型工具往返的理论下限，但属于本项目用户已提出的初始需求，因此第一版保留最简实现。

### Skill 使用

只扫描项目 `.agents/skills/*/SKILL.md`，把名称、描述和绝对路径加入目录提示。模型可以通过 Bash 读取正文和执行配套脚本。Skill 是按需加载的操作说明，不另建执行引擎，也不实现语义检索、安装市场或热插件系统。无 Skill 时照常运行。Project Memory 同样作为可选 Skill 使用，不内置其项目结构、显示器或自动初始化流程。

### 上下文压缩

每次模型请求前估算上下文，给下一次输出预留空间。接近预算时，汇总旧历史并保留近期完整的消息与工具往返。摘要包含用户目标、约束、已验证进展、重要文件、未完成工作和失败。完整原记录仍保存在本机会话中。

压缩改变发送给模型的上下文，不覆盖原始记录。切分只能在完整往返之间，不能留下没有调用的工具结果或没有结果的调用。单轮很长时也要能压缩已完成的早期往返。摘要生成失败时保留原上下文并报告，不清空历史或无限重试；输入本身过大时明确提示。

## 工具数量的取舍

建议第一版只内置 `bash`，其读写和搜索能力足以支持编程闭环。Pi 的 read/edit/write 是值得随后加入的易用性选择，但不属于逻辑上的必需项。若实际任务证明 shell 编辑经常失败，再增加 edit 或 apply_patch，并按真实失败场景测试。这里只是 seeda 的设计选择，不代表 Bash-only 在任何模型或任务下性能都相同。

## 模块建议

只需 cli、agent、model、bash、session/context、skills 六个职责单元，可以是同一包中的普通文件。工具调度用小型名称映射即可；不建立插件注册平台、服务总线或通用框架。初期一个进程、一个会话、一个运行中的用户请求。

## 首轮验收

| 场景 | 必须观察到的行为 |
| --- | --- |
| 连续对话 | 第二次输入能引用第一次交流的内容 |
| 实际编程任务 | 在临时目录读文件、修改代码、执行测试、读失败、继续修复，直到给出结果 |
| 多个工具调用 | 每个调用都有对应结果，顺序执行后模型继续 |
| 工具参数错误与命令失败 | 不执行无效调用，错误反馈给模型，CLI 不崩溃 |
| 取消与超时 | 模型请求或 Bash 可以停止，子进程清理，用户能继续输入 |
| 超长输出 | 返回截断提示与完整输出文件路径，下一次请求仍可执行 |
| Skill | 能发现、按需读取并使用一个包含脚本的项目 Skill |
| 会话加载 | 退出再打开能继续，已完成命令不会被重放；未知结果明确标记 |
| 压缩 | 以小上下文预算强制触发，保留目标与最近往返，能继续任务 |
| 模型异常 | 失败和截断不会被误报为任务完成，也不会执行未完成参数 |

逻辑检查可以使用模拟模型；编程、取消、Skill 和压缩还需真实模型与实际进程验证。当前仅完成设计审阅，没有运行证据。
