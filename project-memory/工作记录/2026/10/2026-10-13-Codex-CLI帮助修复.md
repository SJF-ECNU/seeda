# -h 被发给模型的参数漏洞修复
## 任务计划书
[[openspec/changes/cli-help/design]]，全部完成 [[openspec/changes/cli-help/tasks]]。
## 问题与修复
用户 seeda -h 进入模型循环并读取仓库。原入口把所有未识别 argv 当成 prompt；加入本地帮助/版本、未知选项拒绝与 -- 字面任务处理，位于 configureNetwork、播种、RuntimeClient 和 Session 之前。帮助列出已有种系命令、必填介绍、TUI命令及环境配置，版本明确是通用入口版本。
## 验证
类型检查、50项完整回归和 OpenSpec严格校验通过，完整日志 /tmp/seeda-help-regression.log。新增 tests/cli-help.test.ts 覆盖已有控制socket、空凭据、无效应用代理配置下帮助/版本/未知选项不连接且目录不产生状态；-- -h 通过本地 HTTP 模型验证为显式任务。真实已安装 seeda -h 成功显示帮助。
测试无效代理时最初调用shebang，由 Node --use-env-proxy 在应用运行前解析无效URL而失败；该测试改为直接Node执行，验证应用层 configureNetwork 未调用。没有改动原代理策略，实际全局帮助在当前有效环境通过。
没有连接用户守护、取消其当前其他请求或删除误请求记录；没有真实模型调用。
