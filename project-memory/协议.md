# 项目记忆协议

本协议在不同代码智能体、模型、客户端和会话之间保存任务进度，同时保证仓库仍是事实来源。

## 事实来源优先级

1. 实时命令结果、Git、当前代码和配置。
2. 当前变更规范、已接受设计和可执行脚本。
3. 持续维护的架构、运维和仓库说明。
4. 项目记忆摘要与带时间戳的工作记录。

工作记录只证明某位参与者在某个时间点观察和验证过什么，不能证明现在仍然成立。

## 跟随 Git 版本

`project-memory/`、项目文档关系层、项目本地 Skill 和智能体入口都属于仓库内容，跟随当前 Git checkout 一起版本化。当前工作树中的内容就是当前分支或提交对应的项目上下文，不另外维护一份脱离 Git 的“全局最新记忆”。

切换分支、标签或提交后，先重新读取当前 checkout 的 Project Memory、文档首页和相关工作流，再继续任务；不得继续沿用切换前已经加载但当前版本中不存在或已经变化的状态。当前分支看不到另一分支的记录属于正常版本差异，不自动跨分支复制、搜索或合并。

需要让某项记忆、文档或工作记录在多个分支共享时，使用项目原有的 Git 合并流程进入相应分支。切换前若这些文件存在未提交修改，像处理代码修改一样先明确保留方式，不自动丢弃、重置或隐藏。

## 哪些工作需要记录

受版本控制的产物发生改变、诊断或决策得到验证，或者工作停在下一位参与者必须继承的边界时记录。普通问答和没有形成持久结论的探索不记录。

每个有界目标使用一个工作流；每次有意义的完成、阻塞、取消或移交创建一篇只追加工作记录。并行智能体使用不同工作流，不共同编辑一篇状态日志。

## 任务计划书

每个有界任务（一个工作流）必须绑定一份任务计划书，在开始实质执行前创建或复用。默认从 `project-memory/模板/任务计划书模板.md` 创建到 `project-memory/任务计划/<工作流文件名>.md`；已有计划或适用的 OpenSpec design.md 则沿用原路径，补齐核心内容，不重复复制方案。计划与工作流使用相同的 `workstream` 标识，工作流的“任务计划书”小节链接唯一计划。

计划至少包含目标与范围、总体方案、可验证步骤、步骤状态和未决项。复杂任务再展开职责、数据流、调度、状态恢复、数据接口和容量；小任务可合并章节，不强行套服务架构。已有 OpenSpec tasks.md 时，计划链接该执行清单，不维护重复步骤表。

接管时先读绑定计划，再读最近工作记录，并以当前事实核对。每次关键进展、阻塞或范围变化，更新同一份计划的步骤状态与证据，并同步工作流的当前摘要、阻塞和下一步。新的工作记录必须在“任务计划书”中链接该计划，并注明本次推进的步骤；完成、取消或移交按实际结果更新状态，不将未验证步骤标为完成。

旧工作流再次启动时补齐计划和绑定，注明依据当前证据补建，不改写历史工作记录；已结束任务不批量补写。普通问答不创建工作流或计划。计划用于执行和接续，不增加单独审批流程。

## 接管

1. 确认当前 Git 分支或提交和工作树状态；若刚发生 checkout 切换，放弃切换前缓存的项目上下文。
2. 从当前 checkout 的 `project-memory/首页.md` 进入，读取项目概览和与任务相关的详细笔记。
3. 选择相关工作流，读取目标、状态、结果、阻塞和下一步，先读绑定的任务计划书，再默认读取该工作流最近一篇工作记录。
4. 如果最近记录不足以解释当前状态、决策依据、阻塞、依赖或代码差异，主动按时间由近到远继续查阅当前 checkout 中的相关历史记录、关联工作流和引用来源；获得足以继续任务的信息后停止，不无目的遍历全部历史。
5. 深入所需的权威项目、环境、变更规范和代码引用，并用当前实现与配置核对继承状态和矛盾。

目标、当前证据、阻塞和下一步全部明确后，接管才算完成。

## 持久事实刷新

项目规则、架构、部署方式或其他持久事实发生变化时，完整阅读受影响的权威来源，再更新项目背景、注意事项或环境部署。记录来源冲突和采用依据；静态文档不能冒充实时健康或授权。

## 项目文档维护

创建、移动或明确替代可长期引用的项目文档时，遵循 `docs/文档规范.md`，更新对应分类索引和必要的关系链接。当前目标、最新进展、阻塞和交接仍写入 Project Memory。

旧文档默认保留路径。只有确认文档归属、新位置、全部引用和仓库规则后才移动；重复、冲突或疑似过期内容未核对前不删除、不合并。仓库使用其他文档根时，以文档首页登记的实际路径为准。

工作记录通过两个有语义的列表连接项目文档：

- “参考文档”只链接实质影响本次判断、设计或操作的文档，不记录所有浏览过的文件。
- “文档产物”完整链接本次新建、更新、移动或明确替代的文档，并注明动作和结果。

这两类链接由工作记录单向指向文档。文档侧通过 Obsidian 反向链接和关系图谱查看相关工作记录，不为了回链而在权威文档中重复追加日志。工作流只保留当前目标仍需使用的文档，完整历史留在只追加工作记录中。

当前工作记录自身和工作流的例行状态、下一步及近期记录链接更新不重复列为“文档产物”；若工作流或项目记忆稳定笔记发生了独立、实质的内容变化，则正常列入。Project Memory 协议等每次必读入口也不自动算作“参考文档”，除非它确实影响了本次具体判断。

## 收尾

1. 根据工作记录模板，在 `project-memory/工作记录/YYYY/MM/` 创建新文件。
2. 只记录经过验证的结果和有界证据，引用规范、差异、报告或源码，不复制长篇内容。
3. 填写“参考文档”和“文档产物”；前者只保留实质依据，后者不得遗漏本次发生变更的项目文档。
4. 只更新受影响工作流的状态、结果、阻塞、下一步、当前相关文档和至多五篇近期记录链接；记录链接按时间由近到远排列，便于下一位参与者默认读取最近一篇。
5. 检查元数据、链接、敏感信息和剩余工作。另一位参与者无需原对话即可继续时才完成。

## 元数据

工作记录包含 `status`、时间与时区、`agent`、`client`、`model`、`session_id`、Git 分支和可选提交。只记录运行环境明确提供的值；未知使用 `unknown`，不可用使用 `unavailable`，没有提交使用 `null`。

## 链接与敏感信息

仓库内笔记和项目文档关系使用 Obsidian 双链，源码使用相对 Markdown 链接。可以记录仓库文档已经公开的非敏感拓扑；不得记录凭据、Token、Cookie、密码、私钥、密钥值、完整环境文件、敏感报文、私有产物内容或原始命令输出。
