# 项目背景与当前边界

## 定位、用户与产品面

用户目标为本地 coding CLI，通过任务逐步发展自进化能力；长远支持能力更新与重启唤醒。当前架构见 [[docs/RSI架构设计]]：Git 保存实现，SQLite 保存成长；守护进程只负责存活；A 验证 B 后请求接替主角色，旧版保留供回退。先建设基础循环，再补齐恢复与接替。名称采用当前目录名 seeda。

## 已具备能力

Git、文档关系层、项目记忆、核心与工具循环、TUI、独立版本环境、成长数据库和守护/A/B 接替均已实现；实测范围见当前运行指南。

## 当前边界

核心与接入源码已存在，npm run check、npm test 可执行；TUI、外部守护、SQLite/Git 运行版本管理与最小 A/B 接替已经实现；技术栈为 TypeScript / Node.js，模型为 DeepSeek V4.1 Flash。基础行为见 [[docs/最小CodingAgent蓝本]]，完整首版范围见 [[docs/RSI架构设计]]；最小首版的三个增量已经实现；已实现部分和实测证据见 [[docs/Agent核心实现与验证]]。

## 来源与冲突

来源为初始空目录的现场检查和用户初始化请求；未发现来源冲突。项目说明见 [[README]]，开发规则见 [[AGENTS]]。

## 后续确认的扩展与记忆边界

小核心提供工具、模型、管理三类最小接口。运行时保留session历史，并从实际实现版本.agents/self加载自身指令和显式通用记忆；不自动提取记忆。项目规则取cwd，Project Memory仍通过可选Skill使用，不自动合并到自身记忆。见 [[docs/自身指令与项目规则]]。实施顺序见 [[docs/RSI架构设计#14. 开始实现的步骤]]。

## 实现技术选择

用户确定 TypeScript 与 TUI，不引入 Agent SDK。模型请求与协议自行实现，原生 HTTP/SSE 为当前方案；首个端点为 DeepSeek 官方 Chat Completions；TUI 采用原生终端绘制与 string-width。Python、uv 与模型 SDK 的前述推荐不采用。

## 当前实现

五部分中的核心与接入已完成首轮：17 项测试、类型与 OpenSpec 严格校验通过；DeepSeek 样例完成实际修复、Skill 使用和 session 继续对话。压缩和 thinking 主要有本地协议验证，不能冒充真实模型验收。

## 最小 TUI 进展

TUI 已通过独立变更实现，npm start 在交互终端默认启用；复用核心 run/cancel/事件，不写 session。类型、24 项回归、PTY 和真实 DeepSeek 样例通过。见 [[docs/TUI前端实现与验证]]。版本、守护与 A/B 已实现，托管启动与实测见 [[docs/版本守护与RSI运行指南]]。
