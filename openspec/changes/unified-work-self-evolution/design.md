# 工作与自改单循环：最小简化方案

状态：用户已授权最小实现与完整路径验证；不发布、不重启实验。

## 目标与范围
让同一个 Agent 围绕用户目标自主选择修改项目、检查反馈、改进自身并继续工作。既不强制自改，也不把不自改判定为失败。不新增资源额度、反思调度器、评判 Agent 或新的状态数据库。保留所有现有安全措施。不是删除所有版本状态：工作决策不分阶段，版本接替仍有安全生命周期。

本次只核对当前 checkout 与 ALE 实验，不能把根仓库脏工作树、已发布默认和隔离 seed 当同一版本。根仓库存在大量此前未提交改动，必须保留。实验 seed 为54bf0b7；本方案未改变任一实现。

## 已核对的架构事实
- `src/core/agent.ts:74`：原生 Agent.run 已是模型→工具→结果→模型循环，没有 solve/learn/decision 阶段。
- `src/runtime/worker.ts:11,44`：primary 原本同时获得 bash 和 management；候选仍隔离，不能递归管理主实例。management 已包含 draft/submit/evaluate/evidence/decide/promote/rollback。
- `src/runtime/supervisor.ts:282`：版本管理校验当前来源、候选关系、完成的隔离评估与显式接受，不需要先进入学习阶段。已有 promote acceptReason 可以合并接受和接替请求。
- `src/runtime/supervisor.ts:190,187`：busy 时 select 只记 pending，实际 performSwitch 在整个 run 的 finally。worker 工具说明明确要求当前请求结束。因此长工具循环内申请接替，仍可能迟迟不生效。
- 外部 `/Users/shjf/work/ale-seeda-evolution/stage.ts:142`：solve 禁止全部 management；learn 仅开放创建/验证；decision 才开放接受/接替。不是 Agent 自主选择不自改的干净实验。
- 外部 runner 再叠加评分→反思→学习→配对→决定；最新 seed 的通用yield仅支持让出，具体学习触发属于实验配置。核心与外部复杂度必须分开处理。

## 最小删除或移出项
| 项目 | 方案 |
|---|---|
| solve/learn/decision 三套主线权限及独立交接会话 | 新自主模式取消阶段权限；同一个 primary 工作会话使用既有工具。旧实验文件与记录归档保留，不原地擦除历史 |
| 官方评分才准进入学习、反思 continue/learn/stop JSON、额外纠正循环 | 从日常主循环移除；反馈作为普通工具结果，Agent 自主使用 |
| 每批工具后强制反思 | 不实施此前口头建议；原循环已经能读取工具结果并选下一动作，不再额外调用模型逼其反思 |
| 固定代数/片段结束/清空工作目录才能自改 | 不放入日常运行；项目会话、文件持续存在 |
| 每次自改必须官方榜分提升、固定两臂配对 | 从通用运行要求移出，保留为可选研究测量；不删除原生候选隔离验证和显式接受 |
| Path A 清空任务状态、私有终局审计 | 保留在研究层用于回答迁移/归因问题；持续自主工作模式是另一实验，不能沿用 Path A 名义混算 |

## 保留能力
1. 原生 Agent/Session、项目文件和用户目标，版本化自身指令/记忆/技能，与项目规则保持原有区别。
2. Bash、verify、runtime_records、结构化错误、实际退出码、原始日志和调用计量。评分以项目适配工具提供，不进入核心。
3. Git草稿/提交/候选、真实隔离evaluate、显式接受、版本实际加载证据、失败拒绝/回退。验证完成不等于质量提升，Agent对证据负责。
4. Supervisor 单写者、切换事务、启动失败处理、优先恢复原版本、取消及子进程回收。截断工具调用不执行；未知结果不盲重放。
5. 现有权限、候选/私有数据边界、凭据隔离、官方程序限制。取消阶段限制不等于解除安全权限。
6. 全部受当前版本机制管理的 Agent 代码及同模型参数仍可演化，不缩成提示词/策略更新。外部评分与凭据控制仍不由被测者篡改；不在本轮扩大或缩小已存在的可信边界。

## 同一个循环如何工作
用户目标 → 原生 Agent 看上下文/工具结果 → 自选下一工具 → 结果回到同一会话。

普通工作可以调用 Bash/verify/评分；发现执行方式有不足时，同一 Agent 可调用 management.draft，以 Bash 修改自身代码，再 submit/evaluate/evidence。没有独立“学习者”接管主线，没有必须先取官方分数的条件。选择不改、拒绝候选、继续项目都合法。

只有它显式接受并请求 promote/rollback 时，运行层完成当前整批工具及日志写入，在下一次模型调用前让旧 worker 正常让出。Supervisor 复用现有切换机制停止旧写者、启动选定版本，确认真实 ready/completed，再用同一个会话与项目目录继续原请求。新进程重载自己的工具、模型、指令等版本内容，记录一次实际切换事实；不注入学习考题或强制反思prompt。

已执行工具不重放，不重复追加用户输入，不在正常换版时伪造崩溃/重试，不向客户端发送一个虚假的任务完成。失败按已有恢复顺序处理，显式取消优先。现有通用yield可复用其落盘边界，但不把ALE检查点文件/评分逻辑带进核心。需检查实际worker host路径，不能把版本ID变化等同完整代码已生效。

## 最小实现落点
A. 外层：自主运行直接复用原生Supervisor/primary，不再按阶段猴子补丁限制management；实验适配只提供公开评分、计量、终态审计。无须重写评分器或版本系统。
B. 核心：只补“有已批准的待切换版本时，整批工具后让出并由Supervisor续跑”的正常控制路径。无pending时原循环原样运行，不增加每轮反思调用。
C. 初始指令：只说明用户目标、可用自改能力和证据要求，不规定自改频率/时机、固定思考格式或学习指标。现有安全指令逐条保留，不把适应方法硬编码进永远加载的提示词。

## 验证要求
- 在一个真实请求内完成项目动作→自主工具入口创建候选→修改可执行工具代码→隔离验证→接受→批次边界接替→新版本继续修改同一个项目文件；核对同一session/workspace、真实implementation来源、后续行为。
- 不自改的普通任务完整完成；没有隐式反思模型调用、额外评分或自改配额。
- 候选拒绝后继续旧版；验证失败不接替；再次提交可以走通；不依赖官方分数才能调用自改。
- 批次含多工具、切换前后取消、切换启动失败、切换后再次崩溃、上下文压缩、日志不完整、未知工具结果：不双写、不重复副作用、不绕过回退/隔离。
- 新旧代码都可观察实际版本和自身日志；项目AGENTS不被自身记忆覆盖；候选仍不能修改主实例或读取私有测试。
- 脚本模型只证明机制；另用真实模型+项目任务观察是否自主选用自改，不把“没有自改”自动判定失败。评价目标完成、质量、可靠性、开销与耗时。

## 取舍与边界
没有预算也不强迫终止，则无法保证有限时间内提交、自改或收敛；这是自由行动的边界，不用新强制学习流程掩盖。移除禁止自改的外层约束，可以测出Agent真实选择，但不保证模型一定善于自我改进。

架构不是整体重写：核心已有大部分能力。最小方案是减外层阶段编排，补安全接替后的同任务续跑。将候选验证生命周期保留，与“必须学习阶段”区分开。

## 实现选择
复用原生Supervisor入口作为自主运行路径，不改写或复用旧ALE阶段runner。Agent仅接受可选批次让出回调；worker以现有IPC传递待切换及让出结果，Supervisor复用performSwitch与resume保留同一任务。普通运行无新增模型调用。旧版本无让出能力时保留请求结束后的兼容切换，不伪称支持中途接替。实验seed检查点不整套合并，避免任务触发逻辑入核。

## 当前实现范围与兼容
已仅修改5个运行文件，新增shouldYield回调、IPC让出能力/结果及Supervisor原循环接替续跑。没有新调度器、数据库、反思阶段或环境变量配置。旧ALE runner不修改、不运行；自主入口就是现有Supervisor。目标旧版本无resume能力时安全拒绝续跑，不声称兼容所有旧种系；此交接不替换已经运行的宿主Supervisor模块。
