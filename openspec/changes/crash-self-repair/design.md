# 崩溃后的自主修复

## 定义与责任
崩溃为意外 worker 退出（含未请求的正常退出）、15 秒未 ready、正常监测下 6 秒无心跳。取消、关闭、切换、普通工具/模型错误、评分失败不是崩溃；睡眠宽限保留。进程外 Supervisor 启动恢复；Supervisor 自己死亡时不在进程内自救，外部服务管理需重新启动它，不能自动重放未知任务。

## 最小实现与取舍
沿用现有每个未完成恢复周期最多 3 次启动：前两次当前故障版本，第 3 次上一版本；没有上一版本则终止。不因 ready 重置计数，只有任务完成才重置，防止 ready/崩溃循环。首次启动和版本接替启动失败也先重试同版本。回退不是改进，不自动发布。

Supervisor.run 保留整个用户请求、取消状态和事件接收方；子进程失败后先清理命令与管理操作，再重新启动。新的执行尝试单独记 implementationVersion；同一原 user 不追加。宿主记录故障版本/实例/原因/时间/目标/尝试数/日志位置；恢复 prompt 仅事实和权限边界，不给修复补丁或测试答案。runtime_records 提供当前会话故障事实，stderr 按实例保留有界尾部，不默认注入模型。

修复继续现有 draft→submit→evaluate→accept→promote。回退后从当前可运行版本创建草稿，可读取保存的故障版本差异再移植，不放宽候选必须源自当前版本的安全规则。

预算仍由原外层计费代理和计时器持有，不创建新实验/预算。恢复提供宿主 beforeResume 钩子以检查计费未知、截止时间或基础设施状态；取消在启动前/后均检查。固定版本评测 allowFallback=false；候选沙箱不自动重启。旧版本不声明 resume 支持则停止原请求，下一次用户请求仍可使用该版本。

不引入 Hash、冻结快照协议或新的审批 Gate；使用既有 Git、SQLite、进程身份和完整路径测试。

## 验证
真实 fork + 本地模型 HTTP + 原生工具/管理链：崩溃→同版本→查 runtime_records→草稿修复→原生验证→显式接受→接替→下一请求加载与实际产物。注入启动失败、ready 后再次崩溃、重试耗尽、取消、预算拒绝、固定版本禁止回退、未知工具结果、不支持恢复的旧版本；检查退出状态、实例与切换记录、命令退出码及文件。固定模型仅证明机制，不证明自主改进收益。隔离 SEEDA_HOME/状态库，不触碰现有运行。
