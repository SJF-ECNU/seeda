# 项目记忆

使用仓库内统一的 `project-memory/协议.md`，不创建第二套日志格式。

## 前置条件

确认 `project-memory/首页.md` 和 `project-memory/协议.md` 存在。缺失核心入口时，使用用户级 `project-memory-init` Skill 修复初始化。

## 接管

1. 确认当前 Git 分支或提交和工作树状态。Project Memory、文档图谱和项目本地 Skill 跟随当前 checkout；若刚发生切换，不继续使用切换前缓存的项目上下文。
2. 完整阅读当前 checkout 的 `project-memory/协议.md`，从 `project-memory/首页.md` 进入。
3. 按任务读取项目概览、背景/边界、注意事项或环境部署，再选择相关工作流，先读绑定的任务计划书，再默认读取该工作流最近一篇工作记录。
4. 如果最近记录不足以解释当前状态、决策依据、阻塞、依赖或代码差异，主动从当前工作流开始，按时间由近到远继续查阅当前 checkout 中的相关历史记录和引用来源；获得足以继续任务的信息后停止，不遍历无关历史，也不默认跨分支搜索记录。
5. 用当前代码、配置和项目采用的变更规范核对继承状态；实现前说明矛盾、目标、当前证据、阻塞和下一步。

## 任务计划与进度

遵循协议的“任务计划书”规则：新工作流在实质执行前绑定唯一计划，接管先读计划，旧工作流缺失时按当前证据补建。使用 `project-memory/模板/任务计划书模板.md`，或复用已有计划/OpenSpec design.md。关键进展与范围变化同步计划步骤和工作流摘要；收尾记录链接同一计划及本次步骤，不改写历史记录。

## 持久事实刷新

用户指出项目背景、注意事项或部署信息不完整，或者项目规则、架构、配置、发布方式或环境拓扑实质变化时：

1. 完整阅读受影响的智能体规则与权威来源。
2. 用当前 Git、代码、配置和可执行脚本核对历史文字。
3. 先更新权威来源，再更新项目记忆中足以接管的摘要、冲突和链接。
4. 静态文档事实不写成实时健康或授权；未知项明确写未知。

## 项目文档维护

创建、移动或明确替代可长期引用的项目文档时，先读取仓库的文档规范和文档首页，再更新对应分类索引与必要的关系链接。当前目标、最新进展、阻塞和交接仍写入 Project Memory，不混入权威项目文档。

普通任务不顺手重排无关旧文档。旧文档默认保留路径；只有确认归属、新位置、全部引用和仓库规则后才移动，重复或冲突内容未核对前不删除、不合并。

工作记录的“参考文档”只链接实质影响本次工作的文档；“文档产物”必须链接本次所有新建、更新、移动或明确替代的项目文档并注明动作。由工作记录单向建立关系即可，文档侧使用 Obsidian 反向链接查看历史，不为了回链反复修改权威文档。

## 收尾

工作完成、阻塞、取消或需要移交时：

1. 按协议和 `project-memory/模板/工作记录模板.md` 创建一篇只追加工作记录，填写实质参考文档和全部文档产物。
2. 只更新受影响工作流，记录真实智能体/模型/Git 元数据、验证、剩余工作、当前相关文档和明确下一步。
3. 检查链接、敏感信息和完成声明。另一位参与者无需原对话即可继续时才算完成。

普通问答或没有形成持久结论的探索不创建工作记录。
